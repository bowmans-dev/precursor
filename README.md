<h2 align="center">Why Precursor</h2>

<p align="center"><img src="assets/readme/marketplace/why-team.png" alt="For you and your team. Clean merge or conflict, before you commit: when a teammate touches a file you're editing, you see it on save in a combined diff preview, before anyone commits, pushes or raises a PR / MR. Multi-way combined diffs: everyone's changes to a file in one preview, e.g. a 4 or 5-way diff when the whole team is in it. No server or middleman: your existing GitHub or GitLab repo is the only infrastructure and your provider's token the only sign-in. Sessions: see teammates' branch changes in realtime, sent directly over encrypted peer-to-peer WebRTC. Offline tracking: notified only when someone edits a file of yours: a clean merge to check your logic survived, or a conflict to settle before the pipeline. Target branch previews: the target with everyone's work across parallel branches merged in, e.g. a feature page before the last branch has landed. Realtime comments: review work while it's still being done, before the merge request." width="392"><img src="assets/readme/marketplace/why-agents.png" alt="For your coding agents. Self-correcting agents: each on its own branch, warned before an edit who else is touching that file, and resolving its own conflicts before it commits. A merge queue: finished work tried against your own pre-commit checks, then landed for you. Never pushed, always undoable. Orchestration: skill queues, and targets that land their agents' work in order. Every agent at a glance: what it's doing, when it needs you, how far through its plan it is. Claude Code or GitHub Copilot CLI: in the terminal, or continued in Claude Code's own tab." width="392"></p>
